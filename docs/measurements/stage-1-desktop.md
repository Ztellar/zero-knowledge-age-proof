# Stage 1 — Measurement on the computer

Date: 2026-10-22. Machine: MacBook Pro M1 Pro, 16 GB of RAM, CPU only. RISC Zero 3.0.6
(local `r0vm`, no Bonsai). Guest toolchain: Rust 1.97.0 (rzup); host: Rust 1.99.1.

## What is proven

The guest ([`prover/methods/guest`](../../prover/methods/guest/src/main.rs)) runs
`age_core::verify` on a test ID card generated by [the fixture generator](../../prover/fixtures/gen.py):

- CSCA → DSC → SOD, both RSA 4096 signatures with SHA-256 (PKCS#1 v1.5);
- DG1's hash inside the SOD;
- age 18 or over on 2026-10-22, and a valid document.

`rsa` 0.9.9 and `sha2` 0.10.9 use RISC Zero's accelerated forks (checked in
[`prover/methods/guest/Cargo.lock`](../../prover/methods/guest/Cargo.lock)). Program
cycles: **975,995**.

To reproduce it: the default test ID card now uses the real key sizes (3072/2048); this
measurement used `gen.py --csca-bits 4096 --dsc-bits 4096`. See
[key sizes](chile-key-sizes.md).

## After optimizing

Counting cycles per step inside the guest (`env::cycle_count`) showed that the RSA
signatures were not the problem:

| Step | Before | After | Change |
| --- | --- | --- | --- |
| Reading the inputs | 565,943 | 7,641 | Raw bytes with a length prefix instead of the default serializer, which spends a 32-bit word per byte |
| Parsing the SOD and certificates, building keys | ~240,000 | 21,080 | A minimal copy-free DER reader ([der_walk](../../prover/core/src/der_walk.rs)) instead of decoding everything; RSA keys from modulus and exponent |
| DSC signature (RSA 4096) | ~75,000 | 77,050 | No change: it is the floor |
| SOD signature (RSA 4096) | 81,139 | 74,981 | No change |
| Hashes, age and expiry | 13,015 | 6,364 | — |
| **Program total** | **983,689** | **198,377** | 5.0 times less |

With paging (49,998 cycles) the total fits in a 2^18 segment (262,144). At 212,432 cycles it
did not fit and was padded up to 2^19: that last adjustment halved the time.

| Receipt | Segments | Total cycles | Proving time | Peak RAM | Size | Verification |
| --- | --- | --- | --- | --- | --- | --- |
| Succinct | 1 | 262,144 | **32.8 s** | **2.57 GB** | 223,514 B | 12.9 ms |
| Composite | 1 | 262,144 | 22.8 s | 2.49 GB | 256,250 B | 14.1 ms |

Same method as the initial table: one run per row.

Warning: our own DER reader does not validate complete structures, it only locates fields.
It is safe because everything it returns is covered by a signature verified afterwards, but
it is sensitive cryptographic code and must be reviewed before using it with anything real.

## Reading

- **Shrinking segments pays off less and less.** From 2^20 to 2^18 RAM drops 49% at the cost
  of 56% more time. From 2^18 to 2^16 it drops 48% but time grows 5.4 times. Padding cycles
  grow from 1.18 to 3.24 million.
- **The succinct proof is 218 KiB.** A binary QR code holds about 2,950 bytes: it does not
  fit in one.
- **For a phone, after optimizing:** 2.6 GB of RAM and 33 s on this Mac. A high-end phone
  (12 GB) should manage; a 4 GB one is tight. Confirmed in stage 2.
